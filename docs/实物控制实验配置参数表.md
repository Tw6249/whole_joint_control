## 2. 控制增益总表

PD 控制增益只包含位置环和速度环增益。输入域 EID 除了位置/速度反馈增益 `kp/kd`，还包含观测器增益 `observer_gain_q/observer_gain_dq` 和输入补偿增益 `ku_q/ku_dq`。

为保证 PD 与 EID 的对比不混入反馈增益差异，P1/P2/P3 的 PD 配置已将 `kp/kd` 对齐到 EID 基准值。需要注意：PD 的 `kp/kd` 是电机位置模式增益，EID 的 `kp/kd` 是内部力矩控制计算中的反馈增益，数值对齐用于控制变量一致，但两种控制律并不完全等价。

| 控制方案 | 适用配置 | `kp` | `kd` | `observer_gain_q` | `observer_gain_dq` | `ku_q` | `ku_dq` | 说明 |
|---|---|---:|---:|---:|---:|---:|---:|---|
| PD | P1/P2/P3 PD 配置 | 120.0 | 5.0 | - | - | - | - | 实机位置 PD，命令侧力矩为 0 |
| EID 基准 | P1/P2 EID、P4 O4、P4 U3 | 120.0 | 5.0 | 0.8 | 0.2 | 12.0 | 1.0 | 当前输入域 EID 候选基准 |
| EID O0 | P4 `ko_o0` | 120.0 | 5.0 | 0.0 | 0.0 | 12.0 | 1.0 | 关闭观测器增益 |
| EID O1 | P4 `ko_o1` | 120.0 | 5.0 | 0.2 | 0.05 | 12.0 | 1.0 | 0.25 倍 `K_o` |
| EID O2 | P4 `ko_o2` | 120.0 | 5.0 | 0.4 | 0.1 | 12.0 | 1.0 | 0.50 倍 `K_o` |
| EID O3 | P4 `ko_o3` | 120.0 | 5.0 | 0.6 | 0.15 | 12.0 | 1.0 | 0.75 倍 `K_o` |

上表中的 EID 增益对两个启用关节相同，即 RightHipPitch 和 RightKnee 均使用同一组 `kp/kd`、`observer_gain_*` 和 `ku_*`。若后续发现髋关节或膝关节的力矩代价、误差或噪声响应差异明显，应再拆成逐关节增益表。

## 9. 执行备注

P2 的物理扰动方式仍需在单次实验记录中明确填写，包括扰动对象、开始时间、结束时间、方向和幅值或估计外力。上述 P2/P4 配置只固定控制器和轨迹参数，不包含软件力矩偏置。

P3 的 `preview_mpc` 已被当前控制代码的 `PolicyReferenceInterpolator` 支持；上机前仍建议先用 `--reference-only` 或离线日志确认参考速度、参考加速度和 jerk 没有异常尖峰。

## 10. 日志与实验身份记录

`h1_direct` 会自动把日志写入 `data/<时间戳>/<配置 log_path 文件名>`。例如运行 `config/h1_real_p2_anti_hip_knee_eid.yaml` 后，日志路径形如：

```bash
data/20260622_235836/h1_real_p2_anti_hip_knee_eid_log.csv
```

CSV 每行都会记录实验身份字段：

| 字段 | 含义 |
|---|---|
| `experiment_id` | P1/P2/P3/P4 |
| `condition_id` | 具体实验条件，例如 `P2_EID_anti_phase_manual_disturbance` |
| `repeat_id` | 重复编号，建议运行时用 `--repeat r01`、`--repeat r02` 指定 |
| `disturbance_target` | 扰动对象，例如 `hip`、`knee`、`none` |
| `disturbance_method` | 扰动方式，例如 `manual_push`、`spring_scale`、`software_torque_bias` |
| `config_path` | 本次运行加载的配置文件 |
| `log_path` | 本次运行实际写入的日志路径 |

运行时建议显式指定重复编号和扰动信息，尤其是 P2/P4：

```bash
sudo ./build-h1/h1_direct config/h1_real_p2_anti_hip_knee_eid.yaml \
    --duration 8 \
    --condition P2-H_EID_anti_phase_hip_disturbance \
    --repeat r01 \
    --disturbance-target hip \
    --disturbance-method manual_push
```

P1/P3 无扰动时也建议指定重复编号：

```bash
sudo ./build-h1/h1_direct config/h1_real_p1_lite_hip_knee_pd.yaml \
    --duration 8 \
    --repeat r01 \
    --disturbance-target none \
    --disturbance-method none
```

如果不传 `--duration`，`h1_direct` 会一直运行，直到 Ctrl+C、SIGTERM 或安全保护触发。正式实验建议始终显式传入 `--duration`；P1/P3 建议先用 6--8 秒，P2/P4 因为需要扰动窗口，建议使用 8--12 秒。

每次 `h1_direct` 运行还会在同一日志目录保存 `input_config.yaml`，用于保留当次配置快照，避免后续修改配置后无法复现旧日志。

## 11. P1/P2/P3/P4 批量实验脚本

P1 的 PD/EID 各 5 次重复可以使用脚本自动执行：

```bash
python3 scripts/run_real_p1_batch.py
```

默认是 dry-run，只打印 10 次运行计划，不会让机器人运动。确认顺序、时长和配置无误后，再执行：

```bash
python3 scripts/run_real_p1_batch.py --execute
```

脚本默认参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--repeats` | 5 | 每个方法重复 5 次 |
| `--duration` | 8 | 每次运行 8 秒，到时自动 safe-hold |
| `--pause` | 5 | 两次运行之间暂停 5 秒 |
| `--order` | `alternating` | 按 PD r01、EID r01、PD r02、EID r02 顺序运行 |

正式执行前脚本会要求输入 `RUN_P1`。如果已经完成现场确认并希望跳过这个确认，可使用：

```bash
python3 scripts/run_real_p1_batch.py --execute --yes
```

如果只想补跑某一种方法或从某个重复编号继续：

```bash
python3 scripts/run_real_p1_batch.py --execute --methods pd --start-index 4 --repeats 2
python3 scripts/run_real_p1_batch.py --execute --methods eid --start-index 4 --repeats 2
```

脚本会先执行 `sudo -v` 缓存 sudo 权限，然后每次调用 `sudo -n ./build-h1/h1_direct ...`，并自动向 `h1_direct` 的安全确认提示发送 Enter。批量运行清单会保存到：

```bash
analysis_artifacts/real_p1_batch/p1_batch_manifest_<时间戳>.csv
```

批量实验期间仍需人工看护和急停准备；若任一次返回非零退出码，脚本会停止后续实验。

P2 的 PD/EID 各 5 次重复可以使用类似脚本。默认是 P2-H，即髋关节轻扰动：

```bash
python3 scripts/run_real_p2_batch.py
```

确认 dry-run 的 10 条命令无误后，执行：

```bash
python3 scripts/run_real_p2_batch.py --execute

| `--repeats` | 5 | 每个方法重复 5 次 |

analysis_artifacts/real_p3_batch/p3_batch_manifest_<时间戳>.csv
```

P4 的 `K_o` / `K_u` 参数扫描可以使用脚本自动执行。默认只做无扰动 `K_o` 稳定性扫描，按 O0 -> O5 增益递增顺序运行，每组 3 次：

```bash
python3 scripts/run_real_p4_batch.py
```

默认是 dry-run，只打印 18 条运行计划，不会让机器人运动。确认顺序、时长和配置无误后，再执行：

```bash
python3 scripts/run_real_p4_batch.py --execute
```

P4 脚本默认参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--scan` | `ko` | 默认扫描 O0--O5；可选 `ku` 或 `both` |
| `--groups` | 空 | 指定扫描子集，例如 `o0,o4,o5` 或 `o5,u4` |
| `--target` | `none` | 默认无外扰稳定性扫描；可选 `hip` 或 `knee` |
| `--disturbance-method` | `manual_push` | `--target hip/knee` 时记录到日志中的扰动方式 |
| `--repeats` | 3 | 每个参数组重复 3 次 |
| `--duration` | 8 | 每次运行 8 秒，到时自动 safe-hold |
| `--pause` | 5 | 两次运行之间暂停 5 秒 |
| `--order` | `grouped` | 每个参数组完成所有重复后，再进入下一组 |

若要在 P2 已确定的髋扰动方式下做正式 P4 `K_o` 扫描：

```bash
python3 scripts/run_real_p4_batch.py --execute --target hip --disturbance-method manual_push
```

若 `K_o` 扫描稳定后继续做 `K_u` 扫描：

```bash
python3 scripts/run_real_p4_batch.py --scan ku --execute --target hip --disturbance-method manual_push
```

若只想快速测试最大 `K_o` 和最大 `K_u` 是否能无扰动跑完 8 秒：

```bash
python3 scripts/run_real_p4_batch.py --groups o5,u4 --repeats 1 --execute
```

P4 批量运行清单会保存到：

```bash
analysis_artifacts/real_p4_batch/p4_<scan>_<target>_batch_manifest_<时间戳>.csv
```

若需要按 P1 -> P2 -> P3 -> P4 顺序自动运行所有批量实验，可以使用总控脚本：

```bash
python3 scripts/run_real_all_batches.py
```

默认是 dry-run，只打印将要调用的 4 个子批处理脚本。确认后执行：

```bash
python3 scripts/run_real_all_batches.py --execute
```

总控脚本会先要求输入 `RUN_ALL`，随后给各子脚本传入 `--execute --yes`，避免每个子脚本重复确认。默认顺序和子脚本默认次数如下：

| 批次 | 子脚本 | 默认内容 |
|---|---|---|
| P1 | `run_real_p1_batch.py` | PD/EID 各 5 次，无扰动 |
| P2 | `run_real_p2_batch.py` | PD/EID 各 5 次，默认髋关节 `manual_push` |
| P3 | `run_real_p3_batch.py` | quintic/preview2 各 2 次，无扰动 |
| P4 | `run_real_p4_batch.py` | 默认 O0--O5 的无扰动 `K_o` 扫描，每组 3 次 |

若只想运行其中一部分：

```bash
python3 scripts/run_real_all_batches.py --only p1,p2 --execute
python3 scripts/run_real_all_batches.py --skip p3,p4 --execute
```

若想让总控脚本的 P4 阶段只测试最大 `K_o` 和最大 `K_u`：

```bash
python3 scripts/run_real_all_batches.py --p4-groups o5,u4 --execute
```

总控脚本自身的运行清单会保存到：

```bash
analysis_artifacts/real_all_batch/all_batch_manifest_<时间戳>.csv
```
